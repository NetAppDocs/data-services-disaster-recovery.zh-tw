= 在 NetApp Disaster Recovery 中為 VMware 工作負載建立複寫計畫
:hardbreaks:
:allow-uri-read: 
:icons: font
:imagesdir: ../media/use/


[role="lead"]
新增 vCenter 站台和資源後，請建立 _複寫計畫_ ，以使用 NetApp Disaster Recovery 保護您的 VMware 工作負載。該計畫定義了 VM 的來源和目的地 vCenters 、資源群組、恢復對應以及開機行為。您也可以設定法規遵循與測試排程，並在不影響正式作業資料的情況下執行測試容錯移轉。

*所需 NetApp Console 角色* 執行此任務需要超級管理員、災難復原管理員、災難復原故障轉移管理員或災難復原應用程式管理員角色。link:https://docs.netapp.com/us-en/console-setup-admin/reference-iam-disaster-rec-roles.html["了解NetApp Disaster Recovery中的使用者角色和權限"^].link:https://docs.netapp.com/us-en/console-setup-admin/reference-iam-predefined-roles.html["了解所有服務的NetApp Console存取角色"^].


NOTE: 若要保護 Kubernetes 工作負載，請參閱 link:task-replication-plan-kubernetes.html["建立 Kubernetes 複寫計劃"]。



[[before-you-begin]]
== 開始之前

* 在建立SnapMirror關係之前，請在災難復原之外設定叢集和 SVM 對等關係。
* 如果在 vCenter 層級設定網路映射，災難復原系統會在建立複製計畫時識別這些映射。如果在建立複製計畫後於 vCenter 層級修改或新增網路映射，災難復原系統會在手動編輯複製計畫時識別這些映射。
* 使用 Google Cloud，您只能在複製計畫中新增一個磁碟區或資料儲存。
* 只有當複寫計畫處於以下狀態之一時，才能啟用保護：就緒、故障復原已提交或測試故障轉移已提交。




[[create-the-replication-plan]]
== 建立複製計劃

制定計畫時、請遵循以下準則：

* 為計劃中的所有虛擬機器使用相同的憑證。
* 對計畫中的所有 VMs 使用相同的指令碼。
* 為計畫中的所有虛擬機器使用相同的子網路、DNS 和閘道。

=== 選擇 vCenter 伺服器

首先，選擇來源 vCenter 和目的地 vCenter。

.步驟
. 從災難恢復選單中，選擇 *複寫計畫*。
. 在下拉式選單中，選擇 *vCenter*。
+
image::site-type-toggle.png[網站類型切換的螢幕擷取畫面]

. 輸入複寫計畫的名稱。

名稱只能包含字母、數字和底線。不支援空格、連字符和其他特殊字元。

. 在 *來源 vCenter* 下，從下拉式選單中選擇資料所在的 vCenter。在 *目標* 下，選擇要用作災難恢復目的地的 vCenter。
+
image:dr-plan-create-name2.png["顯示 vCenter 伺服器頁面的螢幕擷取畫面"]

. 選擇“下一步”。

=== 選擇要複製的應用程式並分配資源組

將所需的虛擬機器或資料存放區分組為功能性資源群組。資源群組可讓您使用共同快照來保護一組虛擬機器。您可以在複寫計畫工作流程之外，將虛擬機器指派給資源群組。如需規劃的相關建議，請參閱 link:resource-group.html["資源群組的最佳實務"]。

.步驟
. 如果您已有資源群組，請選擇**資源群組**，選擇資源群組，然後按一下**下一步**。
+
如果您沒有現有的資源群組或需要為資源群組新增資源，請選擇 *虛擬機器*（VM）或 *資料儲存*。

. 從自動產生的清單中選擇要新增至複寫計畫的 VMs 或資料儲存。對於 VM，您可以按資料儲存進行篩選。選擇資料儲存或 VM 後，它會自動新增到資源群組。
+
image:dr-plan-create-apps-vms6.png["螢幕截圖顯示了「新增複製計畫」>「要複製的應用程式」頁面"]

. 在頁面右側、檢閱選取的 VM 或資料存放區。
+
** 若要移除虛擬機器或資料存放區，請將滑鼠懸停在資源名稱上，然後選擇 *X*。
** 若要將資源整理到多個資源群組中，請選擇 *Click to add another resource group*。新增資源群組後，您可以在群組之間拖放資源。選擇鉛筆圖示可編輯資源群組的名稱。
+
image:dr-plan-create-apps-datastores.png["螢幕截圖顯示了「新增複製計畫」>「要複製的應用程式」頁面"]



. 選擇“下一步”。




[[map-source-resources-to-the-target]]
=== 將來源資源映射到目標

在資源對應中，指定來源環境中的資源應如何對應到目標。建立複寫計畫時，您可以為計畫中的每個 VM 設定開機延遲和順序。這可讓您設定 VM 的啟動順序。

如果您打算在複寫計畫中執行測試容錯移轉，則應提供一組測試容錯移轉對應，以確保在容錯移轉測試期間啟動的虛擬機器不會干擾正式作業虛擬機器。您可以透過為測試虛擬機器提供不同的 IP 位址，或將測試虛擬機器的虛擬 NIC 對應到與正式作業隔離的但具有相同 IP 組態的不同網路（稱為 _bubble_ 或測試網路）來實現這一點。

.開始之前
如果您想在此服務中建立 SnapMirror 關係，則叢集及其 SVM 對等關係應該已經在災難恢復之外設定完畢。

.步驟
. 在「資源映射」頁面中，選取該複選框，以便對故障轉移和測試操作使用相同的映射。
+
image:dr-plan-resource-mapping2.png["複製計劃，資源映射選項卡"]

. 在故障轉移映射標籤中，選擇每個資源右側的向下箭頭並映射每個部分中的資源：
+
** 計算資源
** 虛擬網路
** 虛擬機
** 資料儲存






==== 計算資源

「計算資源」區段定義了容錯移轉後虛擬機器的還原位置。將來源 vCenter 資料中心和叢集對應到目標資料中心和叢集。

虛擬機器可以選擇在特定的 vCenter ESXi 主機上重新啟動。如果啟用了 VMware DRS，則可以根據需要自動將虛擬機器遷移到備用主機，以符合已設定的 DR 原則。

您也可以選擇將此複寫計畫中的所有虛擬機器放入 vCenter 清單中的唯一資料夾中。這提供了一種簡單的方法，可在 vCenter 內快速整理容錯移轉的虛擬機器。

.步驟
. 選擇“計算資源”旁的向下箭頭。
. 請提供以下資訊：
+
** *來源資料中心與目標資料中心*
** *目標集群*
** *目標主機*（選用）：選擇叢集後，您可以設定此資訊。
** *資料夾* （選用）





TIP: 如果 vCenter 設定了分散式資源排程器（DRS）來管理叢集中的多個主機，則無需選擇主機。如果選擇主機，災難恢復會將所有虛擬機器放置在所選主機上。* *目標虛擬機器資料夾*（選用）：建立新的根目錄資料夾來儲存所選的虛擬機器。



==== 虛擬網路

虛擬機器使用連接到虛擬網路的虛擬網路卡。在故障轉移過程中，服務會將這些虛擬網路卡連接到目的地 VMware 環境中定義的虛擬網路。對於資源群組中虛擬機器所使用的每個來源虛擬網路，災難恢復都需要指派一個目的地虛擬網路。


NOTE: 您可以將多個來源虛擬網路指派給同一個目標虛擬網路。但這可能會造成 IP 網路配置衝突。您可以將多個來源網路對應到單一目標網絡，以確保所有來源網路具有相同的配置。

.步驟
. 在「容錯移轉對映」標籤中，選擇 *Virtual networks* 旁的向下箭頭。
. 災難恢復會自動填入來源虛擬網路。對於每個來源網路，請從下拉式選單中選擇適當的目的地網路。




==== 虛擬機

您可以透過設定下列任一選項來設定受複製計畫保護的資源群組中的每個虛擬機，以適應目標 vCenter 虛擬環境：

* 虛擬 CPU 的數量
* 虛擬 DRAM 的數量
* IP位址配置
* 作為故障轉移過程的一部分，能夠執行客戶作業系統 shell 腳本
* 能夠使用唯一的前綴和後綴更改故障轉移虛擬機器名稱
* 能夠在虛擬機器故障轉移期間設定重新啟動順序


在「故障轉移對映」標籤中，選擇「*虛擬機器*」旁的向下箭頭。

虛擬機器的預設設定是映射的。預設映射使用與虛擬機器在生產環境中相同的設定（相同的 IP 位址、子網路遮罩和網關）。

如果您對預設設定進行任何更改，則必須將目標 IP 欄位變更為「與來源不同」。


NOTE: 如果將設定變更為“與來源不同”，則需要提供 VM 客戶作業系統憑證。

根據您的選擇，此部分可能會顯示不同的欄位。

您可以增加或減少分配給每個故障轉移 VM 的虛擬 CPU 數量。但是，每個虛擬機器至少需要一個虛擬 CPU。您可以變更分配給每個虛擬機器的虛擬 CPU 和虛擬 DRAM 的數量。您可能想要更改預設虛擬 CPU 和虛擬 DRAM 設定的最常見原因是目標 vCenter 叢集節點沒有來源 vCenter 叢集那麼多的可用資源。


NOTE: 切換 *進階設定* 選項，以新增指令碼並設定應用程式一致性。

*網路設定* NetApp Disaster Recovery 支援豐富的 VM 網路設定選項。如果目標站點上的虛擬網路所使用的 TCP/IP 設定與來源站點上的正式作業虛擬網路不同，則可能需要變更這些設定。

在最基本（和預設）級別，設定只是對目標站點上的每個 VM 使用與來源站點上相同的 TCP/IP 網路設定。這要求您在來源和目標虛擬網路上配置相同的 TCP/IP 設定。

災難恢復支援虛擬機器的靜態或動態主機組態協定（DHCP）IP 組態。DHCP 提供了一種基於標準的動態設定主機網路連接埠 TCP/IP 設定的方法。DHCP 必須至少提供一個 TCP/IP 位址，還可以提供預設閘道位址（用於路由到外部網際網路連線）、子網路遮罩和 DNS 伺服器位址。DHCP 通常用於終端使用者運算設備，例如員工的桌面、筆記型電腦和行動電話連接，同時也可用於任何連網運算設備，例如伺服器。

* *使用相同的子網路遮罩、DNS 和網關設定*選項：由於這些設定對於連接到相同虛擬網路的所有虛擬機器通常都是相同的，因此您可能會發現配置一次這些設定並讓災難復原使用複製計劃保護的資源群組中所有虛擬機器的設定會更容易。如果某些虛擬機器使用不同的設置，則需要取消選取此方塊並為每個虛擬機器提供這些設定。
* *IP 位址類型*：重新設定 VM 組態以符合目標虛擬網路要求。災難恢復提供兩種選項：DHCP 或靜態 IP。對於靜態 IP，設定子網路遮罩、閘道和 DNS 伺服器。此外，輸入 VM 的憑證。
+
** *DHCP*：如果您希望虛擬機器從 DHCP 伺服器取得網路設定訊息，請選擇此設定。如果您選擇此選項，則只需提供 VM 的憑證。
** *靜態 IP*：如果您想手動指定 IP 配置訊息，請選擇此設定。您可以選擇以下之一：與來源相同、與來源不同或子網路對應。如果您選擇與來源相同，則無需輸入憑證。另一方面，如果您選擇使用來自來源的不同訊息，則可以提供憑證、VM 的 IP 位址、子網路遮罩、DNS 和網關資訊。  VM 客戶作業系統憑證應提供給全域層級或每個 VM 層級。
+
當將大型環境還原到較小的目標叢集或進行災難復原測試而無需配置一對一的實體 VMware 基礎架構時，這會非常有用。

+
image:dr-plan-vm-subnet-option2.png["螢幕截圖顯示新增複製計劃 > 資源映射 > 虛擬機"]



* *腳本*：您可以將自訂的訪客作業系統託管腳本（.sh、.bat 或 .ps1 格式）作為後處理程序包含在內。借助自訂腳本，災難復原可以在故障轉移、故障復原和遷移過程之後執行您的腳本。例如，您可以使用自訂腳本在故障轉移完成後還原所有資料庫事務。該服務可以在運行 Microsoft Windows 或任何受支援的 Linux 變體的虛擬機器中運行腳本，並支援命令列參數。您可以將腳本指派給單一虛擬機，也可以指派給複製計畫中的所有虛擬機。
+
若要啟用虛擬機器客體作業系統的指令碼執行，必須符合下列條件：

+
** 必須在虛擬機器上安裝 VMware Tools。
** 必須提供適當的使用者憑證以及足夠的來賓作業系統權限才能執行該腳本。
** （可選）包括腳本的超時值（以秒為單位）。
+
*執行 Microsoft Windows 的虛擬機器*：可以執行 Windows 批次腳本 (.bat) 或 PowerShell (ps1) 腳本。Windows 腳本可以使用命令列參數。以 `arg_name$value`格式設定每個參數，其中 `arg_name`是參數名稱， `$value`是參數值，每個 `argument$value`配對之間以分號分隔。

+
*執行 Linux 的虛擬機器*：可以執行虛擬機器使用的 Linux 版本支援的任何 shell 腳本 (.sh)。 Linux 腳本可以使用命令列參數。在以分號分隔的值清單中提供參數。不支援命名參數。將每個參數新增到 `Arg[x]`參數列表並使用指標引用每個值 `Arg[x]`數組，例如， `value1;value2;value3` 。



* *降級虛擬機器硬體版本並註冊*：如果目標 ESX 主機版本早於來源版本，請選擇此項，以便在註冊期間進行配對。
* *保留原始資料夾層次結構*：預設情況下，災難復原會在故障轉移時保留虛擬機器清單層次結構（資料夾結構）。如果復原目標_不_具有原始資料夾層次結構，則災難復原功能會建立它。
+
取消選取此方塊可忽略原始資料夾層次結構。

* *目標虛擬機器前綴和後綴*：在虛擬機器詳細資料中，您可以選擇為每個故障轉移虛擬機器名稱新增前綴和後綴。這有助於區分故障轉移虛擬機器和在同一 vCenter 叢集上執行的生產虛擬機器。例如，您可以為虛擬機器名稱新增前綴 "DR-" 和後綴 "-failover" 。有些人會新增第二個生產 vCenter ，以便在災難事件中將虛擬機器暫時主機在不同的站台。新增前綴或後綴可以幫助您快速識別故障轉移虛擬機器。您也可以在自訂指令碼中使用前綴或後綴。
+
您可以使用在計算資源部分設定目標 VM 資料夾的替代方法。

* *CPU* 和 *記憶體容量（GB）*：在虛擬機器詳細資料下，您可以選擇調整虛擬機器的 CPU 和記憶體容量。
+

NOTE: 您可以以千兆位元組 (GiB) 或兆位元組 (MiB) 為單位配置 DRAM。雖然每個虛擬機器至少需要 1MiB 的 RAM，但實際數量必須確保虛擬機器來賓作業系統和任何正在運行的應用程式能夠有效運作。

* *開機順序*：您可以在容錯移轉後，修改跨資源群組中所有選取 VM 的開機順序。預設情況下，所有 VM 會平行一起開機；不過，您可以在此階段進行變更。這有助於確保所有優先順序一的 VM 都在後續優先順序的 VM 啟動之前執行。
+
災難復原會並行啟動所有啟動順序號碼相同的虛擬機器。

+
** 循序開機：為每個虛擬機器指派唯一的編號，以便依指派的順序開機，例如 1、2、3、4、5。
** 同時啟動：為任何虛擬機器指派相同的編號，以便同時啟動它們，例如 1,1,1,1,2,2,3,4,4。


* *啟動延遲*：調整啟動操作的延遲時間（分鐘），表示虛擬機器在啟動程序之前等待的時間。輸入 0 到 10 分鐘之間的數值。
* *應用程式一致*：指示是否建立應用程式一致的快照複本。此服務會先靜止應用程式、再擷取快照、以取得應用程式的一致狀態。此功能支援在 Windows 和 Linux 上執行的 Oracle 、以及在 Windows 上執行的 SQL Server 。請參閱下一節以取得更多詳細資料。
+
您必須切換此選項的 *Advance settings* 開關。如果啟用應用程式一致性，則必須提供使用者名稱和密碼形式的認證資料。

==== 建立應用程式一致的副本

==== 資料儲存

VMware 資料儲存庫託管在ONTAP FlexVol磁碟區或使用 VMware VMFS 的ONTAP iSCSI 或 FC LUN 上。使用資料儲存部分定義目標ONTAP叢集、儲存虛擬機器 (SVM) 以及磁碟區或 LUN，以將磁碟上的資料複製到目標。

選擇 *資料儲存* 旁的向下箭頭。系統將根據所選虛擬機器自動選擇資料儲存對應。

根據您的選擇，此部分可能會啟用或停用。

image:dr-plan-datastore-platform.png["螢幕截圖顯示了“新增複製計劃”>“資源映射”>“資料儲存區”"]


TIP: 在做出這些選擇之前，請先查看 link:concept-replication-plan.html#platform-managed-backups["關於平台代管備份（即 ONTAP 代管的快照）的資訊"]。

* *使用平台代管的備份和保留排程*：如果您使用外部快照管理解決方案，請選取此核取方塊。災難恢復支援使用外部快照管理解決方案，例如原生 ONTAP SnapMirror 原則排程器或第三方整合。如果複寫計畫中的每個資料存放區（Volume）都已經有在其他位置代管的 SnapMirror 關係，則可以將這些快照用作災難恢復中的恢復點。
+
選取此選項時，災難恢復不會設定備份排程。但是，您仍然需要設定保留排程，因為可能仍會為了測試、容錯移轉和容錯回復作業而建立快照。

+
配置完成後，服務不會定期拍攝任何快照，而是依賴外部實體來拍攝和更新這些快照。

* *備份和保留開始時間*：輸入您希望備份和保留開始執行的日期和時間。
* *備份和保留頻率*：請輸入以小時和分鐘為單位的時間間隔。例如、如果您輸入 1 小時、則服務將每小時建立一次快照。
* *所有資料存放區的保留計數*：輸入要保留的快照數量。
+

TIP: 保留的快照數量以及每個快照之間的資料變化率決定了來源和目標上消耗的儲存空間量。保留的快照越多，消耗的儲存空間就越多。

* *來源資料儲存與目標資料儲存*：如果存在多個（連出）SnapMirror 關係，您可以選擇要使用的目的地。如果 Volume 已建立 SnapMirror 關係，則會顯示對應的來源資料儲存和目標資料儲存。如果 Volume 沒有 SnapMirror 關係，您可以立即建立關係：選擇目標叢集、選擇目標 SVM 並提供 Volume 名稱。服務將建立 Volume 和 SnapMirror 關係。
+

NOTE: 如果您想在此服務中建立 SnapMirror 關係，則叢集及其 SVM 對等關係應該已經在災難恢復之外設定完畢。

+
** 如果虛擬機器來自相同磁碟區和相同 SVM，則該服務將執行標準ONTAP快照並更新輔助目標。
** 如果虛擬機器來自不同的磁碟區和相同的 SVM，則該服務將透過包含所有磁碟區來建立一致性群組快照並更新輔助目標。
** 如果虛擬機器來自不同的磁碟區和不同的 SVM，則該服務透過包含相同或不同叢集中的所有磁碟區來執行一致性群組啟動階段和提交階段快照，並更新輔助目標。
** 容錯移轉期間，您可以選擇任何快照。如果您選擇最新快照，服務將建立隨需備份，更新目的地，並使用該快照進行容錯移轉。
